## Docs

Папка `docs` содержит документацию о продукте: требования, архитектура, фичи, качество, безопасность, эксплуатация.

Структура папки — только перенесённые разделы:

- `project/` — структурная часть проекта: требования к реализации (`product-requirements.md`), роадмап (`roadmap.md`), терминология (`terminology.md`), сценарии использования (`user-flow.md`), пользователи и роли (`user-roles.md`)
- `architecture/` — принципы и правила архитектурных решений и взаимодействий: обзор системы, модель данных, API-контракты, интеграции
- `features/` — структура и реализация фичей проекта
- `backend/` — документация по backend-структуре: модули, сервисы, API handlers, data access, интеграции, фоновые задачи, ошибки и observability
- `frontend/` — документация по frontend-структуре: страницы, routes, компоненты, state management, API usage, формы, auth states, loading/empty/error states, accessibility
- `quality/` — принципы тестирования и работы с качеством
- `security/` — структура и реализация безопасности проекта: доступы, угрозы, секреты, классификация данных
- `operations/` — процесс эксплуатации: окружения, деплой, откаты, бэкапы, мониторинг

В каждой папке есть свой `work-rules-*.md` — с него стоит начинать изучение раздела.

## Разделение слоёв документации

`team/` описывает процесс работы команды (задачи, статусы, приёмка, архитектурные решения). `docs/` описывает сам продукт (требования, архитектура, фичи, качество, безопасность, эксплуатация). При конфликте источник правды — `team/` и скилы ролей (см. `team/DECISIONS.md`, D-001).

Правила работы с файлами:
- Update together with содержит документы, которые нужно проверять при изменении текущего файла.
- Update trigger описывает события, при которых документ нужно обновить.
- История изменений не ведётся вручную в паспорте, для этого используется git.
