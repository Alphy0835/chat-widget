# Команда мечты — шаблон виртуальной команды для Claude Code

Шаблон проекта, где разработку ведёт команда агентов: тим лид планирует и принимает работу, исполнители (бекенд, фронтенд, QA, безопасник, дизайнер) выполняют задачи в отдельных чатах.

## Как начать новый проект

1. Скопируй эту папку целиком и переименуй под проект.
2. Открой в папке Claude Code, в первом чате вызови `/team-lead` и опиши, что хочешь построить.
3. Тим лид задаст вопросы, заполнит паспорт проекта (`team/PROJECT.md`), сделает `git init` и создаст первые задачи.

## Рабочий цикл

1. **Планирование**: в чате тим лида — `/team-lead`, обсуждаете, он создаёт задачи в `team/tasks/` с критериями приёмки и советует модель для каждой.
2. **Выполнение**: открываешь **новый чат**, выбираешь рекомендованную модель, вызываешь скил роли и называешь задачу: `/backend TASK-001`. Исполнитель работает в своей ветке и сдаёт отчёт.
3. **Приёмка**: возвращаешься в чат тим лида (или открываешь новый и вызываешь `/team-lead`) и пишешь: «прими TASK-001». Тим лид проверяет по критериям, гоняет тесты и либо мержит в main, либо возвращает с замечаниями.
4. Повторяешь. Независимые задачи можно вести в нескольких чатах параллельно.

## Скилы

| Команда | Роль |
|---|---|
| `/team-lead` | Тим лид — планирование, выбор модели, приёмка |
| `/backend` | Бекенд-разработчик |
| `/frontend` | Фронтенд-разработчик |
| `/qa` | Тестировщик |
| `/security` | Безопасник (ревью, код не правит) |
| `/designer` | Дизайнер (макеты в `team/design/`) |

## Подсказки

- Один чат = одна роль = одна задача. Так контекст не смешивается. Связку «сделал бекенд → сразу проверил QA» лучше вести двумя задачами, но можно и одним чатом: сначала `/backend`, после сдачи в том же чате `/qa`.
- Чат тим лида можно переиспользовать, пока он помнит контекст; если чат распух — просто открой новый и вызови `/team-lead`, он восстановит картину из `team/`.
- Все правила лежат в `team/PROTOCOL.md` — если хочешь изменить процесс, правь этот файл, скилы на него ссылаются.
