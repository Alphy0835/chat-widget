# Дизайн-система виджета — тема «pravoe-delo.su» (default theme v2)

Источник данных: computed styles сняты напрямую с https://pravoe-delo.su/ (не по памяти/скриншоту) 2026-08-11. Дополняет `team/DECISIONS.md` D-005/D-006 конкретными значениями для переноса в код TASK-003 (`widget/src/widget.css`, `widget/src/widget.js`, `demo.html`).

Это **новая дефолтная тема** виджета (см. TASK-004, п.6): значения ниже — то, что подставляется, когда сайт-клиент не передал свои `data-*` атрибуты. Через `data-primary-color` / `data-position` тема по-прежнему полностью переопределяется — жёстко «под pravoe-delo.su» ничего не зашивается.

Других оттенков оранжевого на сайте как основного акцента не найдено (один нестандартный `#FA6D00` встретился на одном декоративном баннере — это не системный цвет, не переносим).

## 2. Шрифт

**Решение: системный fallback-стек, БЕЗ подключения Google Fonts (`@import`/`<link>`) внутри Shadow DOM.**

```css
font-family: "Roboto Condensed", "Arial Narrow", Arial, sans-serif;
```

### Обоснование

- Виджет ставится на **произвольные** сайты, не только pravoe-delo.su (см. D-004: изоляция и лёгкость встраивания — ключевое требование). Собственный `@import`/`<link>` на Google Fonts — это лишний внешний HTTP-запрос на чужом сайте при каждой загрузке страницы, дополнительная задержка первого рендера панели и потенциальный конфликт с CSP хоста (`font-src`/`connect-src`), который мы не контролируем и не можем продиагностировать заранее.
- Текста в виджете на этом этапе мало (заголовок шапки, заглушка, плейсхолдер) — цена подключения веб-шрифта ради нескольких строк текста не оправдана, особенно с учётом стека без сборки (D-004: «без внешних зависимостей без необходимости»).
- **Компромисс вместо жёсткого выбора:** `@font-face`/`<link>`, объявленные в `<head>` **основного документа** хоста, доступны и элементам внутри Shadow DOM — шрифты не скоуплены границей shadow-дерева (в отличие от CSS-стилей). На pravoe-delo.su сайт **сам уже подключает Roboto Condensed через Google Fonts** для своего контента (проверено: `fonts.gstatic.com` в ресурсах страницы). Значит на этом конкретном сайте виджет получит точный брендовый шрифт **бесплатно**, без единого дополнительного запроса от самого виджета. На сайтах, где Roboto Condensed не загружен, произойдёт мягкая деградация до `"Arial Narrow"` (похожий по пропорциям узкий гротеск, есть в Windows/большинстве браузерных движков) и далее до обычного `Arial`.
- Итог: первый шрифт в стеке — «бонус», если он уже есть на странице; последний — гарантированно рабочий fallback. Zero-risk, zero extra requests.

Если в будущем частота установки на сайты без предзагруженного Roboto Condensed окажется высокой и точность бренда станет важнее — можно завести отдельную задачу на подключение шрифта через `@font-face` с `font-display: swap` и локально захостенным файлом шрифта (не Google Fonts CDN, чтобы не тянуть третью сторону) внутри Shadow DOM. Не делаем сейчас, т.к. не запрошено и добавляет сложность без подтверждённой необходимости.

### Начертания

| Токен | Вес | Где |
|---|---|---|
| `--cw-font-regular` | 400 | Текст заглушки, плейсхолдер поля ввода |
| `--cw-font-semibold` | 600 | Заголовок шапки (было 600 в TASK-003 — без изменений, совпадает с весом кнопок сайта: `font-weight: 600` подтверждено computed style) |

Заголовки/H1 самого сайта визуально жирнее (кажутся ~700), но у виджета нет крупных заголовков — только надпись в шапке (15px) — там достаточно 600, увеличение до 700 на таком мелком кегле не даст заметной разницы и не нужно.

## 4. Мобильная ширина

Наследуется без изменений от TASK-003 (медиа-запрос `@media (max-width: 480px)` в `widget.css`, см. §3 выше). Тема pravoe-delo.su не меняет breakpoint, пропорции или логику адаптива — только цвет и шрифт, которые применяются одинаково на всех ширинах.

## 5. Состояния

| Элемент | Состояние | Стиль |
|---|---|---|
| Плавающая кнопка | default | фон `--cw-primary`, тень `0 4px 16px rgba(0,0,0,0.24)` |
| Плавающая кнопка | hover | `transform: scale(1.05)`, `filter: brightness(90%)`, тень `0 6px 20px rgba(0,0,0,0.3)` |
| Плавающая кнопка | active/pressed | `filter: brightness(85%)` |
| Кнопка отправки | default (текст введён) | фон `--cw-primary` |
| Кнопка отправки | hover | `filter: brightness(90%)` |
| Кнопка отправки | disabled (поле пустое/весь виджет-заглушка) | `opacity: 0.5`, `cursor: not-allowed` — без изменений от TASK-003 |
| Поле ввода | disabled (текущий этап — заглушка) | серый фон `#F9FAFB`, текст-плейсхолдер `#9CA3AF`, `opacity: 0.5` — без изменений |
| Кнопка закрытия (шапка) | hover | `background: rgba(255,255,255,0.15)`, `opacity: 1` — без изменений, работает поверх любого `--cw-primary` |

`filter: brightness()` выбран вместо второго hex-токена `--cw-primary-hover`, потому что акцентный цвет настраивается через `data-primary-color` (D-004/D-005) под произвольный сайт — brightness-фильтр даёт корректный hover-эффект автоматически для **любого** заданного цвета, без необходимости вычислять и хардкодить тёмный вариант под каждый конкретный бренд.

## 6. Что переносить в код (для `/frontend`)

Изменений HTML-структуры (`widget.js` — разметка `.cw-root`) **не требуется**. Всё — правки CSS-переменных и стилей в `widget/src/widget.css`:

1. `.cw-root { --cw-primary: #2563eb; ... }` → `--cw-primary: #ff4800;` (новое значение по умолчанию).
2. `.cw-root, .cw-root * { font-family: ...; }` → заменить текущий системный стек на `"Roboto Condensed", "Arial Narrow", Arial, sans-serif;`.
3. Добавить `filter: brightness(90%)` в `.cw-button:hover`, `.cw-send-btn:hover` (сейчас `.cw-send-btn` не имеет hover-правила и постоянно `disabled` — добавить на будущее, когда кнопка станет активной); добавить `:active { filter: brightness(85%); }` там же.
4. `demo.html` — обновить `data-primary-color="#2563EB"` на `data-primary-color="#FF4800"` в примере сниппета (демонстрирует новую дефолтную тему «из коробки»); либо оставить как есть и явно показать, что старое значение — пример **переопределения** дефолта. Решает фронтендер/тим лид — не критично для этой задачи.

Геометрия, радиусы, тени, breakpoint — без изменений (см. §3), трогать не нужно.
