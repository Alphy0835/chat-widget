## Контекст

Сейчас окно чата — визуальная заглушка (`widget/src/widget.js`, `team/DECISIONS.md` D-005): статичный текст-плейсхолдер, поле ввода и кнопка отправки задизейблены. Пользователю нужно протестировать виджет через реальный, пусть и упрощённый, диалог — без ИИ, без бэкенда, чисто «вопрос из списка → готовый ответ». Формат и способ загрузки данных зафиксированы в D-008.

## Задание

Реализуй в `widget/src/widget.js` (+ стили в `widget/src/widget.css` при необходимости) сценарный движок поверх существующей области `.cw-messages`:

1. При первом открытии панели — приветственное сообщение бота + кнопки категорий из `window.ChatWidgetQA.categories`. Если `window.ChatWidgetQA` не подключен на странице — красиво деградируй: оставь текущую заглушку-плейсхолдер (как сейчас), без ошибок в консоли.
2. Клик по категории → в чат добавляется сообщение-бот со списком кнопок вопросов этой категории (`questions`, отфильтрованные по `categoryId`) + кнопка «‹ Все категории».
3. Клик по вопросу → в чат добавляются две реплики: реплика «пользователя» с текстом вопроса и реплика «бота» с текстом ответа. После ответа — кнопки «Другие вопросы этой категории» и «Все категории».
4. Разметка чата различает реплики пользователя и бота (разные классы/выравнивание), сохраняется существующая визуальная тема (D-007). Прокрутка `.cw-messages` при накоплении сообщений — вниз к последнему сообщению.
5. Поле ввода и кнопка отправки остаются как есть (disabled) — вне рамок этой задачи.
6. Обнови `demo.html`: подключи `widget/data/qa-data.js` тегом `<script>` перед виджетом (с тестовой заглушкой на 3–5 пар, если TASK-006 к моменту работы ещё не готов — заглушку удалишь/оставишь по своему усмотрению, после мержа TASK-006 файл станет полным).
7. Обнови докистрину по цепочке «Update together with»: заполни `docs/features/` новым файлом фичи по шаблону `docs/features/feature-template.md` (например `docs/features/FEAT-001-linear-dialog.md`) и добавь сценарий в `docs/project/user-flow.md` (таблица Flow Index + блок Flow).

Не входит в задачу: контент вопросов-ответов (TASK-006), свободный текстовый ввод/поиск, любая интеграция с бэкендом или ИИ.

## Критерии приёмки

- [ ] Открытие виджета с подключённым `qa-data.js` показывает приветствие и кнопки категорий (проверить в `demo.html` через `python3 -m http.server`)
- [ ] Клик по категории показывает список вопросов этой категории и кнопку возврата
- [ ] Клик по вопросу добавляет в чат реплику вопроса и реплику ответа, реплики визуально различимы (пользователь/бот)
- [ ] После ответа показаны кнопки «Другие вопросы этой категории» и «Все категории», обе рабочие
- [ ] Без подключённого `window.ChatWidgetQA` виджет не падает в консоли и показывает текущий плейсхолдер
- [ ] Проверено на демо-странице с намеренно «кривыми» стилями хоста (`demo.html`) — стили и логика виджета не ломаются (сохраняется изоляция Shadow DOM, D-004)
- [ ] Проверено на мобильной ширине (эмуляция ~375px) — кнопки и сообщения не переполняют панель
- [ ] Создан/обновлён файл в `docs/features/` и добавлен сценарий в `docs/project/user-flow.md`
