## Контекст

Первая продуктовая задача проекта. Нужно реализовать визуальную оболочку встраиваемого чат-виджета согласно `team/DECISIONS.md`:
- D-004 — технология (чистый JS, без фреймворков) и способ встраивания (один `<script>`-тег, монтирование в Shadow DOM);
- D-005 — визуальный MVP-паттерн (плавающая кнопка → окно чата, нейтральная цветовая схема, настройка через `data-*` атрибуты).

Реальной логики общения (отправка/получение сообщений, backend, ИИ-агент, Битрикс24) в этой задаче нет — она появится позже отдельными задачами.

## Задание

Создать структуру виджета в репозитории, например:
- `widget/src/loader.js` — скрипт, который сайт-клиент подключает через `<script>`; читает `data-*` атрибуты своего тега, создаёт контейнер на странице и монтирует Shadow DOM с виджетом;
- `widget/src/widget.js` — логика рендеринга виджета внутри Shadow DOM (кнопка, окно чата, открытие/закрытие);
- `widget/src/widget.css` (или стили инлайном через `<style>` внутри Shadow DOM) — оформление виджета;
- `demo.html` в корне репозитория — тестовая страница сайта-хоста с собственными (в т.ч. намеренно конфликтующими) стилями, подключающая виджет ровно тем сниппетом, который в реальности вставляется на сайт клиента.

Функционал:
- Loader поддерживает конфигурацию через `data-*` атрибуты script-тега, минимум: `data-widget-id`, `data-position` (`bottom-right` по умолчанию, `bottom-left`), `data-primary-color`.
- Плавающая круглая кнопка-иконка чата в углу экрана согласно позиции из конфига.
- Клик по кнопке разворачивает панель чата: шапка (название/иконка-заглушка, кнопка закрытия), область сообщений с текстом-заглушкой («Чат скоро заработает» или похожее), неактивное поле ввода и disabled-кнопка отправки.
- Повторный клик по кнопке или кнопка закрытия в шапке — сворачивает панель обратно в кнопку.
- Плавные CSS-переходы при открытии/закрытии.
- Полная изоляция стилей через Shadow DOM в обе стороны: стили сайта не влияют на виджет, стили виджета не просачиваются на страницу.
- Адаптивность: на экранах уже 480px окно чата занимает почти весь экран.
- Разумный, но достаточный `z-index`, чтобы виджет был поверх типового контента страницы.

Что НЕ входит в задачу (границы):
- Реальная отправка/приём сообщений, WebSocket, HTTP-запросы к какому-либо API;
- Backend на Python, авторизация, интеграция с Битрикс24;
- Брендирование под конкретного клиента (логотип, кастомные шрифты);
- Бандлер/минификация/TypeScript — файлы должны работать как обычные браузерные скрипты без шага сборки. Если считаешь, что бандлер нужен уже сейчас — не делай сам, опиши в «Замечания для тим лида».

## Критерии приёмки

- [ ] Открытие `demo.html` в браузере показывает плавающую кнопку в правом нижнем углу экрана
- [ ] Клик по кнопке открывает панель чата (шапка, область-заглушка сообщений, неактивное поле ввода); повторный клик или кнопка закрытия в шапке сворачивают её обратно
- [ ] Сниппет встраивания в `demo.html` не длиннее ~15 строк и соответствует реальному способу вставки на сайт клиента (проверить построчно)
- [ ] Конфликтующие глобальные стили на `demo.html` (например `button { all: unset; color: red; }`, `* { box-sizing: content-box !important; }`) не меняют вид виджета; стили виджета, в свою очередь, не влияют на остальную страницу
- [ ] На ширине экрана <480px (эмуляция мобильного в devtools) окно чата занимает почти весь экран и остаётся usable (кнопка закрытия доступна, текст не обрезан)
- [ ] Позиция (`data-position`) и основной цвет (`data-primary-color`) реально меняют вид виджета при смене атрибутов в `demo.html`
- [ ] В зависимостях виджета нет сторонних фреймворков/библиотек (React/Vue/jQuery и т.п.), нет шага сборки — файлы работают напрямую как обычные `<script>`/`<link>`
- [ ] `docs/frontend/frontend-docs.md` и `docs/architecture/system-overview.md` обновлены с учётом нового модуля
- [ ] `team/PROJECT.md`, раздел «Как запускать», заполнен конкретными шагами
