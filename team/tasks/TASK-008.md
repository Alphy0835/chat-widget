## Контекст

Сейчас у виджета только кнопочная навигация (категории → вопросы → ответ), см. `team/DECISIONS.md` D-008 и `widget/src/widget.js` (движок из TASK-007). Пользователь хочет текстовое поле ввода вопроса вместо/вместе с кнопками, но без ИИ и без бэкенда — ответ по-прежнему берётся из готовой базы `widget/data/qa-data.js`. Подход зафиксирован в `team/DECISIONS.md` → D-009: нечёткий поиск (fuzzy-search) через библиотеку Fuse.js, результат — список вопросов-кандидатов кнопками (не автоматический ответ), чтобы не подсунуть неверный юридический ответ на неточно сформулированный запрос.

## Задание

1. Вендори Fuse.js: скачай конкретную стабильную версию (UMD/min-сборку) и закоммить как `widget/vendor/fuse.min.js`. Никаких CDN-подключений в рантайме — только локальный файл, чтобы не сломать сценарий работы через `file://` (D-008) и не тянуть внешний трафик на сайте клиента. В отчёте укажи, какую версию и откуда взял.
2. Добавь в разметку виджета текстовый ввод вопроса — либо активируй существующее поле ввода в футере (сейчас `disabled` по D-005), либо сделай отдельное поле — выбери вариант, исходя из текущей вёрстки `widget/src/widget.js`/`widget/src/widget.css`, сохрани тему D-007.
3. По отправке текста (Enter или кнопка): добавь реплику пользователя с введённым текстом, выполни поиск Fuse.js по `questions[].question` (при необходимости добавь вопросам необязательное поле `keywords: []` в `widget/data/qa-data.js` для 3–5 вопросов как пример синонимов — не обязательно покрывать все 24).
4. Если есть релевантные совпадения — сообщение бота со списком 2–4 лучших кандидатов кнопками («Возможно, вы имели в виду:»). Клик по кандидату — как обычный клик по вопросу (переиспользуй существующий `showAnswer`).
5. Если совпадений нет (score хуже подобранного тобой порога) — сообщение «точный вопрос не найден» + кнопка «Все категории».
6. Не ломай существующий кнопочный сценарий категорий — он остаётся рабочим как есть, поиск текстом — альтернативный путь к тем же данным.
7. Обнови `demo.html`, если нужно подключить `widget/vendor/fuse.min.js`.
8. Обнови документацию по цепочке «Update together with»: дополни `docs/features/FEAT-001-linear-dialog.md` (или заведи отдельный `docs/features/FEAT-002-...`, если решишь, что это отдельная фича) и добавь альтернативный сценарий в `docs/project/user-flow.md` (FLOW-001 или новый Flow).

Не входит в задачу: реальный ИИ/NLP-разбор запроса, интеграция с бэкендом, изменение существующей кнопочной навигации по категориям.
