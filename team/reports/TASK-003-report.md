## Что сделано

- `widget/src/loader.js` — единственный файл, который подключается на сайте клиента через `<script>`-тег. Синхронно читает `document.currentScript`, вычисляет базовый URL, парсит `data-widget-id` / `data-position` / `data-primary-color`, создаёт контейнер и монтирует `Shadow DOM` (`mode: "open"`); подгружает `widget.css` (`<link>`) и `widget.js` (`<script>`) относительно своего расположения и после загрузки вызывает `window.ChatWidget.mount(...)`.
- `widget/src/widget.js` — рендер UI-оболочки внутри переданного shadow root: плавающая кнопка, панель чата (шапка с иконкой-заглушкой, названием и кнопкой закрытия; область сообщений с текстом-заглушкой; неактивные поле ввода и кнопка отправки). Открытие/закрытие по клику на кнопку и по кнопке закрытия в шапке, через CSS-класс `cw-open` на корневом элементе. Цвет применяется через CSS-переменную `--cw-primary`, позиция — через атрибут `data-position` на корневом элементе.
- `widget/src/widget.css` — оформление: круглая кнопка 60×60 (56×56 на мобильных), панель 360×520 со скруглением 16px, плавные CSS-переходы (opacity/transform) при открытии/закрытии, позиционирование `bottom-right`/`bottom-left` через атрибут-селекторы, `:host { all: initial; }` для доп. изоляции, `z-index: 2147483000`. Медиа-запрос `max-width: 480px` — панель занимает почти весь экран (отступы 8px).
- `demo.html` — тестовая страница сайта-хоста с намеренно конфликтующими глобальными стилями (`button { all: unset; color: red; }`, `* { box-sizing: content-box !important; }`, `input { all: unset; border: 3px dashed lime !important; }`) и сниппетом подключения виджета (6 строк, ровно как на реальном сайте клиента).
- `.claude/launch.json` — конфиг локального статического сервера для просмотра demo.html через Browser pane (не часть деливери, вспомогательный файл; в коммит не включён).
- Обновлены `docs/frontend/frontend-docs.md` (Purpose, Frontend Scope, Components, State Management, Design System Usage), `docs/architecture/system-overview.md` (Main Modules, Data Flow, External Dependencies), `team/PROJECT.md` (раздел «Как запускать»).

## Как проверить

1. Из корня репозитория: `python3 -m http.server 4173`.
2. Открыть `http://localhost:4173/demo.html` в браузере.
3. Должна быть видна плавающая синяя круглая кнопка в правом нижнем углу поверх «кривой» страницы сайта-хоста.
4. Клик по кнопке — разворачивается панель чата (синяя шапка «Чат с поддержкой» + крестик, текст-заглушка по центру, внизу неактивное поле ввода и disabled-кнопка отправки). Повторный клик по кнопке (иконка меняется на крестик) или клик по крестику в шапке — сворачивает панель обратно.
5. Обычная кнопка/поле сайта под текстом (`Кнопка сайта`, `Поле сайта`) должны остаться красной unstyled-кнопкой и полем с зелёной пунктирной рамкой — стили виджета на них не попали.
6. В DevTools включить эмуляцию мобильного экрана (например 375×812) и перезагрузить страницу — открытая панель занимает почти весь экран, крестик закрытия и текст доступны, не обрезаны.
7. В `demo.html` временно поменять `data-position="bottom-left"` и `data-primary-color="#16A34A"` в теге `<script>` внизу файла, перезагрузить страницу — кнопка должна стать зелёной и переехать в левый нижний угол. Не забыть вернуть значения обратно (`bottom-right` / `#2563EB`) — в сданной ветке они уже дефолтные.

## Замечания для тим лида

Тестирование кликов через Browser pane инструмента `computer` (клик по экранным координатам) не всегда попадало по кнопке внутри Shadow DOM — похоже на особенность самого инструмента автоматизации браузера (несовпадение координатного пространства скриншота и вьюпорта), а не баг виджета. Функциональность подтверждена через реальные DOM-события `click()` на элементах внутри shadow root (эквивалентно клику пользователя — тот же слушатель `addEventListener`) плюс визуально скриншотами. Если при ручной проверке мышью в обычном браузере кнопка не будет реагировать на клик — сообщите, но по коду и по event-based тестам это исправная стандартная кнопка без изменений.

Прочих проблем вне рамок задачи не обнаружено.
