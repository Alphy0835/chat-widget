## Что сделано

1. Проверил фирменный стиль https://pravoe-delo.su/ напрямую в браузере (`getComputedStyle` на реальных элементах сайта, не по памяти/скриншоту): акцентный цвет кнопок `rgb(255, 72, 0)` = `#FF4800`, шрифт `"Roboto Condensed", Arial, sans-serif` (font-weight 600 на кнопках), радиус кнопок 10px, белый фон, чёрный текст, сайт сам подключает Roboto Condensed через Google Fonts (`fonts.gstatic.com` в ресурсах). Всё совпало с зафиксированным в `team/DECISIONS.md` D-006, ничего уточнять/дополнять не пришлось.
2. Создал `team/design/design-system.md` — полное текстовое описание новой дефолтной темы виджета: цвета (hex), шрифт (стек + обоснование выбора), геометрия/радиусы/тени/отступы (px, зафиксировано явно, хотя большинство значений не менялось от TASK-003/D-005), состояния (default/hover/active/disabled).
3. Создал `team/design/mockups/widget-pravoe-delo-theme.html` — статичный HTML/CSS-прототип, открывается в браузере без сборки. Показывает три состояния рядом: закрытая плавающая кнопка, кнопка при hover, открытая панель чата — плюс заметки по поведению под каждым макетом и легенду токенов внизу. Проверил визуально в браузере (скриншоты по всем трём блокам) — рендерится корректно, fallback-шрифт срабатывает.
4. Решил вопрос шрифта (см. design-system.md §2): **системный fallback-стек `"Roboto Condensed", "Arial Narrow", Arial, sans-serif`, без собственного `@import`/`<link>` на Google Fonts внутри Shadow DOM.** Ключевой аргумент: `@font-face`, объявленный в `<head>` документа-хоста, доступен элементам внутри Shadow DOM (шрифты не скоуплены границей shadow-дерева) — на pravoe-delo.su сайт уже сам грузит Roboto Condensed, поэтому виджет получит точный брендовый шрифт бесплатно, без единого дополнительного запроса. На сайтах без предзагруженного шрифта — мягкая деградация до Arial Narrow/Arial. Это избавляет от выбора «точность бренда vs лишний запрос на чужом сайте» — оба варианта учтены одним стеком.
5. Явно решил, что HTML-структура `widget.js` изменений не требует — только значения CSS custom properties и стилей в `widget/src/widget.css` (см. design-system.md §6, с построчным списком правок для фронтендера).

2. Убедиться, что видно три блока: закрытая кнопка (оранжевый круг), кнопка hover (чуть темнее/крупнее/с более глубокой тенью), открытая панель чата (оранжевая шапка, белое тело, серая заглушка текста, неактивные поле ввода/кнопка отправки).
3. Сверить конкретные значения (цвета, px, шрифт) с `team/design/design-system.md` — они совпадают 1:1 с инлайн-стилями прототипа.

## Замечания для тим лида

1. **Смена дефолтного цвета виджета с `#2563EB` на `#FF4800`.** Задание явно просило сделать оранжевый новой дефолтной темой (не только для pravoe-delo.su), это сделано в дизайне (design-system.md §1, §6) — но это меняет визуальный дефолт, зафиксированный в D-005 («стартовая цветовая схема нейтральная, primary `#2563EB`»). Технически это не архитектурное решение (цвет и так конфигурируется через `data-primary-color`, D-004/D-005), но фактически переопределяет значение из D-005 текстом. Возможно, стоит явно отразить это как обновление/дополнение D-005 в `team/DECISIONS.md` при приёмке — на усмотрение тим лида.
2. Добавил в дизайн `filter: brightness()` для hover/active плавающей кнопки и кнопки отправки (раньше у кнопки отправки не было hover-стиля вообще, у плавающей кнопки — только scale+тень без изменения цвета). Это не было явно в TASK-003, но нужно для консистентного фидбека под любой сконфигурированный акцентный цвет (не хардкодил отдельный hover-hex именно под оранжевый — чтобы работало и для других сайтов/цветов). Считаю это минорным UI-улучшением в рамках темы, не отдельной задачей — но если тим лид не согласен, можно вырезать при приёмке.
3. Логотип/брендирование «Правое дело» внутри виджета не добавлял — по границам задачи это явно не входит в объём.
4. Следующий шаг — перенос дизайна в код `widget/src/*`, отдельная задача для `/frontend` (упомянута тим лидом как «заведу после приёмки этой задачи»).
