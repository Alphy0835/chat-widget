## Что сделано

1. `widget/src/widget.js` — добавлен сценарный движок диалога поверх `.cw-messages`:
   - `getQaData()` — валидация `window.ChatWidgetQA` (проверка, что это объект с массивами `categories` и `questions`); при отсутствии/некорректном формате движок не запускается.
   - `startDialogIfNeeded()` — запускается один раз при первом открытии панели (`setOpen(true)`): очищает плейсхолдер, показывает приветствие, дисклеймер (если задан в данных) и кнопки категорий.
   - `showCategories()` / `showQuestions(category)` / `showAnswer(question, category)` — переходы между экранами сценария (категории → вопросы категории → вопрос-ответ → возврат).
   - `appendMessage/appendBotMessage/appendUserMessage` — рендер реплик через `textContent` (без `innerHTML`, без риска инъекции разметки из данных).
   - `appendButtons()` — рендер кнопок; клик по любой кнопке группы дизейблит всю группу (`disableButtonGroup`), чтобы нельзя было повторно кликнуть уже отработавший вариант, история диалога остаётся видна.
   - Автопрокрутка `.cw-messages` вниз при каждом добавлении сообщения/группы кнопок.
2. `widget/src/widget.css` — стили сценария: `.cw-messages-chat` (переключает `.cw-messages` из центрированной заглушки в колонку сообщений), `.cw-msg` / `.cw-msg-bot` / `.cw-msg-user` (разное выравнивание и цвет — фон/акцент под тему D-007), `.cw-msg-note` (дисклеймер), `.cw-buttons` / `.cw-chip-btn` (кнопки-варианты, состояние `:disabled` для уже кликнутых).
3. `widget/data/qa-data.js` — новый файл, тестовая заглушка из 5 пар вопрос-ответ в 2 категориях по схеме D-008 (реальный контент — TASK-006, формат/переменная не меняются).
4. `demo.html` — подключён `<script src="widget/data/qa-data.js">` перед `loader.js`.
5. Документация:
   - `docs/features/FEAT-001-linear-dialog.md` — новая фича по шаблону `feature-template.md`.
   - `docs/project/user-flow.md` — заполнен `FLOW-001` (Flow Index + блок сценария), паспорт файла переведён в `Status: active`.

Не входило в задачу и не менялось: контент вопросов-ответов (TASK-006), свободный текстовый ввод, интеграция с бэкендом/ИИ.

## Как проверить

```bash
python3 -m http.server 4173
```

Открыть `http://localhost:4173/demo.html`.

1. Кликнуть по плавающей кнопке чата (правый нижний угол) — должно появиться приветствие, дисклеймер и кнопки категорий «Банкротство физлиц» / «Долги и кредиты».
2. Кликнуть по категории — появляется список вопросов категории и кнопка «‹ Все категории», предыдущая группа кнопок становится неактивной (бледнее).
3. Кликнуть по вопросу — добавляются реплика вопроса (справа, оранжевый фон) и реплика ответа (слева, серый фон), затем кнопки «Другие вопросы этой категории» / «Все категории» — обе рабочие, возвращают к соответствующему экрану.
4. В DevTools удалить/закомментировать подключение `widget/data/qa-data.js` в `demo.html` и перезагрузить страницу — при открытии виджета должен остаться исходный текст-плейсхолдер «Чат скоро заработает…», в консоли не должно быть ошибок.
5. В DevTools включить эмуляцию мобильного устройства (~375px) — панель должна занимать почти весь экран, кнопки и сообщения не должны переполнять её по ширине.
6. Убедиться, что «кривые» стили `demo.html` (`button { all: unset; color: red }`, `* { box-sizing: content-box !important }` и т.д.) не влияют на вид виджета и наоборот.
