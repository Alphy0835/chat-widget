## Что сделано

1. `widget/vendor/fuse.min.js` — вендорена библиотека **Fuse.js v7.0.0** (UMD/min-сборка), скачана с `https://cdn.jsdelivr.net/npm/fuse.js@7.0.0/dist/fuse.min.js` и закоммичена как локальный файл. В рантайме CDN не используется — только `<script src="widget/vendor/fuse.min.js">`.
2. `widget/src/widget.js`:
   - Поле ввода в футере (`.cw-input`) и кнопка отправки (`.cw-send-btn`) переведены из `disabled` в активное состояние (было заделом на будущее по D-005/D-007). Если `window.ChatWidgetQA` не подключён/некорректен — оба элемента принудительно дизейблятся в JS (`if (!qaData) { inputEl.disabled = true; sendBtn.disabled = true; }`), чтобы не показывать рабочее поле поиска без данных для поиска.
   - `getFuse()` — лениво создаёт индекс `Fuse` по `qaData.questions` (поля `question` вес 0.7, `keywords` вес 0.3, `threshold: 0.4`, `ignoreLocation: true`); если `window.Fuse` не загружен — возвращает `null`, ниже по цепочке это ведёт к ветке «не найдено» без ошибок.
   - `showSearchResults(queryText)` — берёт до 4 лучших результатов `fuse.search()`; если результатов нет — сообщение «Точный вопрос не найден. Попробуйте выбрать вопрос из категорий.» + кнопка «Все категории»; если есть — сообщение «Возможно, вы имели в виду:» + кнопки-кандидаты, клик по кандидату вызывает существующий `showAnswer(question, category)`.
   - `handleSearchSubmit()` — по Enter в поле или клику по кнопке отправки: добавляет реплику пользователя (`appendUserMessage`), очищает поле, вызывает `showSearchResults`.
   - `showAnswer()` слегка доработан: кнопка «Другие вопросы этой категории» теперь добавляется только если категория найдена (защита от края случая, не встречается в текущих данных, но безопаснее).
   - Кнопочный сценарий категорий не менялся по логике.
3. `widget/src/widget.css` — `.cw-input` больше не выглядит как disabled-заглушка (цвет текста `#111827` вместо серого, добавлен `::placeholder` и `:focus` с обводкой в акцентный цвет), добавлен `min-width: 0`, чтобы длинный текст в поле не распирал строку ввода на узких экранах.
4. `widget/data/qa-data.js` — добавлено необязательное поле `keywords: []` для 5 вопросов (q-002, q-006, q-011, q-013, q-017) как пример синонимов/опечаток для поиска. Остальные 19 вопросов не тронуты, ищутся по `question` без `keywords`.
5. `demo.html` — добавлен `<script src="widget/vendor/fuse.min.js"></script>` перед `loader.js` (после `qa-data.js`).
6. Документация:
   - `docs/features/FEAT-001-linear-dialog.md` — дополнена (не заведён отдельный FEAT-002): описание текстового поиска в Description, обновлены Related data model/tests/Update trigger, Related Systems, Implementation Links, Security Impact, Test Notes, Release Notes. Решил не заводить отдельную фичу, так как поиск — это альтернативный путь к тому же экрану/данным того же движка, а не самостоятельная фича (формулировка самого D-009 — «поверх кнопочного сценария»).
   - `docs/project/user-flow.md` — в FLOW-001 добавлен блок «Текстовый поиск вместо кнопок» в Alternative Scenarios, обновлены Preconditions и Related Docs.

Не входило в задачу и не менялось: реальный ИИ/NLP-разбор запроса, интеграция с бэкендом, кнопочная навигация по категориям (логика не менялась, только косвенно затронута в `showAnswer` защитой на случай отсутствия категории).

## Как проверить

```bash
python3 -m http.server 4173
```

Открыть `http://localhost:4173/demo.html` (также проверено прямое открытие `demo.html` как `file://` — работает идентично, `window.Fuse` и `window.ChatWidgetQA` доступны, поиск отрабатывает).

1. Кликнуть по плавающей кнопке — открывается диалог с приветствием и кнопками категорий, поле ввода внизу активно (не серое/disabled).
2. Кнопочный сценарий: категория → вопросы → ответ → «Другие вопросы»/«Все категории» — работает без изменений (регрессий нет).
3. Ввести в поле текст с опечаткой, например «заберут ли кватиру», нажать Enter (или кнопку отправки) — реплика пользователя добавляется, бот отвечает «Возможно, вы имели в виду:» и показывает 1–4 кнопки-кандидата (в т.ч. «Заберут ли у меня квартиру при банкротстве?»). Клик по кандидату — реплика вопроса + готовый ответ + кнопки возврата, как в обычном сценарии.
4. Ввести нерелевантный текст, например «какая сегодня погода на марсе», отправить — бот отвечает «Точный вопрос не найден. Попробуйте выбрать вопрос из категорий.» + кнопка «Все категории», в консоли браузера ошибок нет.
5. Проверить на мобильной ширине (~375px, DevTools device toolbar) — поле ввода, длинный введённый текст и кнопки-кандидаты не переполняют панель по ширине (текст в поле скроллится внутри инпута, кнопки-кандидаты переносятся на несколько строк, но не вылезают за края).
6. В DevTools удалить/закомментировать подключение `widget/vendor/fuse.min.js` в `demo.html`, оставив `qa-data.js` — при отправке текста должно появиться «Точный вопрос не найден…» (поиск недоступен деградирует туда же, без ошибок в консоли).
